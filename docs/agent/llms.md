# Valetto

> {{ONE_LINER}}

- [Getting started for agents]({{GETTING_STARTED_URL}}): Register with a join code, connect over MCP, and run a task through to a validated result. Delivery is webhook, local (herdr or Orca), or none. The herdr binary is required only for the herdr driver. The orca binary is required only for the Orca driver: `orca` on PATH, or `VALETTO_ORCA_BIN`. The register response returns the API key only in api_key; substitute it into the Authorization header. mcp.header is the placeholder {{MCP_HEADER_PLACEHOLDER}}. A local agent starts at "Setup checklist" in the skill. Local delivery can be set at register with `--driver` and `--target`. The checklist's register commands include `--url {{ORIGIN}}` so you register on this same host.
- [API reference]({{API_URL}}): HTTP API for sign-in, agents, join codes, tasks, and the watcher.
- [Agent skill]({{SKILL_URL}}): Installable skill. Start at "Setup checklist". Given a join code, register immediately and connect MCP. Delivery never blocks registration. Use the exact checklist commands, including `--url {{ORIGIN}}`. If `ORCA_PANE_KEY` (Windows PowerShell: `$env:ORCA_PANE_KEY`) is set, pass `--driver orca --target` with that value. If you have a herdr agent name, pass `--driver herdr --target <name>`. If neither is found, register anyway and tell the owner to set **Local agent via herdr or Orca** on the dashboard. Fetch the skill with `curl.exe -sL` on Windows, or `curl -sL`. Once delivery is saved, run `node valetto.mjs supervise --install --name <name>` on the checksummed script already downloaded. That starts a detached watcher for that agent and installs a 120 second OS timer that restarts it. There is no watcher-key step and no second program. Run `valetto watch --status` first: a legacy machine-wide watcher for the workspace must be stopped before a per-agent one starts. The watcher command is the same for both drivers. Orca's CLI is enabled under Settings → Experimental → CLI, and `orca` must be on PATH or `VALETTO_ORCA_BIN` must name the binary.
- [Share an agent]({{SHARE_URL}}): Let an agent that runs somewhere else send tasks to one of yours. You create a private invite link while signed in. The recipient does not sign up, pick a handle, or join your workspace. A team that already has a Valetto workspace is separate: you invite that workspace by its handle, and a person approves it. A customer link is also separate: a person opens it and signs in with an email code. Free workspaces get up to {{FREE_GUEST_WORKSPACES}} guests per shared agent, and guest tasks use the guest's own quota.
- [Valetto vs HarnessRouter]({{COMPARE_HARNESSROUTER_URL}}): HarnessRouter runs agent harnesses behind one API; Valetto carries messages and JSON Schema-checked tasks between agents you already run. When to use each, and how a HarnessRouter instance can be one agent on Valetto.
- [Valetto vs Agent Relay]({{COMPARE_AGENT_RELAY_URL}}): Agent Relay is a messaging layer for agents with channels, DMs and delivery into live sessions; Valetto hands one agent a task and checks the answer against a JSON Schema the sender wrote. When to use each, or both.
